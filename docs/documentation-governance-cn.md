## 目标

让仓库文档在中英文两条主线上都持续与当前代码、运行时行为和运维流程保持一致。

## 归属模型

### 仓库入口文档

- `README.md`
- `README-CN.md`

负责：

- 项目定位
- 架构摘要
- 快速开始
- 文档导航

不负责：

- 完整 API 细节
- 详细部署手册
- 详细前端模块行为

### `docs/` 下的正式文档

- `api*.md` 负责接口覆盖与分组说明
- `deployment*.md` 负责环境、启动、Docker 与运维说明
- `testing*.md` 负责回归、冒烟与门禁说明
- `security*.md` 负责安全基线与发布前检查
- `frontend-architecture*.md` 负责前端结构与数据流
- `rag-architecture*.md` 负责检索设计与迁移上下文
- `documentation-package-index.md`、`documentation-change-record.md`、`documentation-quality-report.md` 负责文档审计清单、变更追踪与质量签核产物

### 子系统入口文档

- `frontend/README*.md` 负责前端路由、鉴权模型与集成说明

### 版本与发布追踪

- `CHANGELOG.md` 负责面向使用者的版本变更记录
- 本文档负责文档流程与治理规则

## 事实来源规则

- 代码与测试是一级事实来源
- 配置文档必须对照 `.env.example`、`docker-compose.yml` 与运行时 settings 模型
- API 文档必须对照 FastAPI routers 与应用启动入口
- 前端文档必须对照 `frontend/package.json`、路由文件、共享 layout 与 domain hooks

## 必须更新文档的触发条件

当以下内容变化时，必须同步更新文档：

- API 端点、请求结构、鉴权要求或响应行为
- 环境变量、Docker 默认值、启动命令或依赖约束
- 前端路由、导航结构或领域接入模式
- harness run 生命周期、审批、验证、studio 或 provider 管理行为
- 检索默认值、记忆行为、interrupt 与 resume 语义

## 双语同步规则

- 中英文对应文档必须在同一批变更中更新
- 除非确有必要，两种语言的章节结构应保持对称
- 端点列表、命令、版本号和文件路径必须等价
- 内部审计产物在仅作为发布复核交付物、且当前没有维护中的英文对照文件时，可以按中文单语维护

## 版本控制与可追溯性

- 对外可见的版本变化统一记录到 `CHANGELOG.md`
- 关键技术文档应在适当位置注明版本范围或校验日期
- 优先通过链接指向事实归属文档，避免在多个入口重复大段内容
- 当行为变化时，必须同时更新归属文档与引用该事实的概览文档

## 评审清单

合并文档变更前，至少确认：

- 文档描述与代码、测试一致
- 中英文内容已同步
- 命令可在仓库根目录执行
- 版本号与依赖名称准确
- 文件路径与接口路径正确
- 概览文档与正式文档之间不存在冲突

## 团队评审角色

- 后端评审负责 API、配置、队列、持久化与运行时行为
- 前端评审负责路由、鉴权、UI 接入与 domain hooks
- 平台评审负责部署、Docker、冒烟与发布门禁

## 推荐变更流程

1. 先确定事实归属文档
2. 在代码或测试中核对行为
3. 同步更新中英文文档
4. 如果变更对外可见，同步更新 `CHANGELOG.md`
5. 执行相关校验命令
6. 涉及后端、前端、运维跨域变更时，请发起跨角色评审

## 非目标

- 本文档不替代产品规划
- 本文档不负责定义实现架构本身
- 本文档不要求所有内部临时草稿都必须双语化
